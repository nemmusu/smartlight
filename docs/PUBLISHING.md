# Repository publication

[English](PUBLISHING.md) · [Italiano](PUBLISHING.it.md)

The repository export contains application sources, tests, user documentation, demonstration screenshots and issue templates. Local configurations, development environments, build outputs, diagnostic captures and private QA reports are excluded by an explicit file list.

## Before the first public release

1. Select a project license and review the licenses of included source code and dependencies. No project license has been assigned automatically.
2. Publish to `github.com/nemmusu/smartlight` with author `nemmusu` and the GitHub noreply address; do not add coauthor attribution.
3. Use the English README as the landing page, with its Italian translation linked at the top.
4. Add a short description: **Tapo and PC RGB lighting control for Windows and Linux, with effects, schedules, Italian/English UI and MCP for AI assistants.**
5. Suggested topics: `tapo`, `smart-lighting`, `rgb`, `openrgb`, `corsair`, `mystic-light`, `mcp`, `desktop-app`, `windows`, `linux`, `python`.
6. Publish verified installer artifacts as release attachments, add their actual download links to the README, and include checksums.
7. Configure a private security reporting channel before accepting vulnerability reports.

No project license has been selected yet. This does not grant redistribution rights to vendor SDKs; their terms remain separate. Keep license decisions here until a project license is explicitly chosen.

Keep MSI marked **experimental / no physical hardware validation**. Do not redistribute the MSI DLL without establishing redistribution permission. Do not describe every OpenRGB catalog model as tested hardware.

The release source and repository ZIPs are generated by `installer/export_source.py` and `installer/export_repository.py`. Screenshots use simulated devices and contain no real account credentials.
